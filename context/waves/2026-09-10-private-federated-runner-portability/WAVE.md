# Wave: Private Federated Runner Portability

Status: Active; Pulse 01 authorized
Implementation authority: One private owner-runner correction
Successor authority: None

## Systems-development gap

The corrected private enterprise-corpus qualification stopped on Windows
before Ferris launched the `EC-05` maximum-input case. The owner runner expanded
256 workspace-relative changed paths into absolute arguments below a long
private custody root, causing process creation to exceed the Windows command
line limit. Earlier cases remained in memory and are not observed evidence.

The measurable decision is whether one bounded owner-side launch correction can
execute the unchanged federated matrix on Windows and hosted Ubuntu while
preserving every input, expected outcome, repetition, and identity check.

## Research basis

- The failed attempt and its evidence semantics are recorded in
  [`Corrected private enterprise-shape corpus qualification`](../../../docs/research/2026-09-10-corrected-private-enterprise-corpus-qualification.md).
- The parent
  [`corrected qualification wave`](../2026-09-10-corrected-enterprise-corpus-qualification/WAVE.md)
  grants no retry or runner-fix authority.
- The existing public 256-input regression launches Ferris from the application
  root and passes application-root-relative changed paths. This is prior art
  for the process boundary, not authority to change Ferris.

## Authorized slice

- private corpus `EC-05` only;
- inspect the existing runner and the public maximum-input regression;
- modify only `tools/run-federated.ps1`;
- set the Ferris child working directory to the declared application root;
- pass the application file and every in-root changed path relative to that
  root while preserving the existing absolute outside-path typed failure;
- preserve all scenarios, 256-input cases, expected outcomes, repetitions,
  identity checks, owner commands, topology, fixtures, and evidence schema;
- run the unchanged complete matrix on Windows;
- create at most one private pull request for hosted Ubuntu validation; and
- retain private repository identity and raw output outside this public tree.

## Completion condition

- the launch correction is limited to path representation and working
  directory;
- the maximum-input and maximum-mixed-input cases each still supply exactly 256
  inputs;
- all unchanged federated scenarios and typed failures pass on Windows;
- the private pull request's existing hosted Ubuntu workflow passes;
- no product, scenario, fixture, manifest, or evidence-schema file changes; and
- the public closeout records only `EC-05`, aggregate outcomes, and claim
  boundaries.

## Stop conditions

Stop rather than expand if the correction requires:

- a Ferris product, schema, dependency, or command change;
- dropping, batching, truncating, or otherwise changing an input;
- changing an expected outcome, repetition, identity assertion, scenario,
  fixture, owner command, or evidence contract;
- a second corrective approach;
- another private repository;
- retrying the exhausted qualification; or
- merging the private pull request without separate user direction.
