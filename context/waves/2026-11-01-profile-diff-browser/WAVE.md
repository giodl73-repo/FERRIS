# Profile evidence comparison in a browser

Owner request: continue the portfolio's Rust/WASM self-service work. This wave
adapts the existing experimental profile-diff reader task to supplied bytes;
it does not revive or enlarge any closed conformance or diagnostic authority.
The product decision is whether a reader can inspect the same bounded evidence
changes without installing the CLI. Research basis: implemented profile-diff
in the closed read-only planning wave, its Pulse 14 contract and Pulse 15 nine-
family development matrix, and the current FERRIS_PROGRAM command inventory.

## Bounded sequence

1. Pulse 01: extract one shared strict byte parser and comparator, retaining
   the native file adapter and its existing path-bound failure identities.
   Add a content-bound in-memory entrypoint, native equivalence tests and a
   minimal WASM consumer. Max effort: 90 minutes and one corrective portability
   repair, then stop and record the evidence. Completion: all 14 existing native
   profile-diff tests, byte/file canonical equality, negative/error classifications,
   resource bounds and a release WASM build pass. No browser publication claim.
2. Pulse 02: after a value checkpoint, complete the browser reader task and
   existing portfolio delivery pattern. Budget: one product/delivery pulse,
   no new validation/custody architecture or diagnostic successor chain.
   Completion: own inputs, native/WASM parity, worker failure/stale fencing,
   source/build/legal downloads, hosted checks and exact live verification.

Abandon this technical approach if it requires owner process execution,
filesystem emulation, semantic reimplementation, relaxed identity/limit rules,
new profile generation or another architectural layer. Two consecutive invalid
attempts stop autonomous work under repository rules. An abandoned scout is not
a native-only exception unless evidence actually establishes that boundary.

## Ownership and rollback

ferris-core owns the existing strict JSON parsing, canonical digests, diff paths,
classes and typed records. The file adapter retains missing/unreadable/non-file
behavior and complete native request binding. A standalone browser adapter owns
input transport and UI, not Cargo or owner truth. Removal is additive: remove
the companion and memory entrypoint; the unchanged native CLI remains usable.
No dependency or owner-workflow adoption is required in other repositories.

No profile generation, support/freshness/approval/readiness/compatibility claim,
Cargo discovery, graph inference, command execution, scheduling, remote evidence,
held-out construction/scoring/oracle access, or diagnostic authority is included.
Only public development fixtures and explicitly authored inputs may be used.
