# Wave: Post-Portability Enterprise Corpus Qualification

Status: Complete; Pulse 01 passed
Implementation authority: One evidence-only qualification pulse
Successor authority: None

## Decision

Run one fresh qualification of unchanged current Ferris against the five-family
private enterprise-shape synthetic corpus after both separately validated
owner-tooling portability corrections merged.

This is a new qualification. It does not reuse or reinterpret either exhausted
qualification attempt as qualification evidence.

## Research basis

- The most recent
  [`qualification attempt`](../../../docs/research/2026-09-10-corrected-private-enterprise-corpus-qualification.md)
  retained 17 Windows records but stopped before durable federated or hosted
  Ubuntu evidence.
- The separate
  [`federated runner correction`](../2026-09-10-private-federated-runner-portability/WAVE.md)
  preserved every scenario and both 256-input boundaries while removing the
  observed Windows process-launch blocker.
- The original
  [`enterprise corpus qualification`](../2026-09-10-enterprise-corpus-qualification/WAVE.md)
  defines the owner-first evidence boundary and public-safe corpus labels.

## Frozen scope

- one public Ferris product revision with no product delta since the prior
  attempts;
- five exact corrected private default-branch revisions;
- existing immutable scenario tags, topology contracts, owner-domain
  declarations, owner commands, strict integrity checks, and evidence schemas;
- local Windows and GitHub-hosted Ubuntu;
- public-safe labels `EC-01` through `EC-05`; and
- private custody for repository identities, revisions, paths, raw output,
  executable hashes, run identities, and identifiable timings.

## Authorized execution

- build the frozen Ferris revision once per platform;
- run every corpus owner-integrity gate;
- run every existing declared scenario with its existing repetitions,
  independent Cargo/application oracle, selected owner command, and full owner
  command;
- retain matched failures and typed rejections as expected non-success
  controls;
- create at most one temporary hosted-validation branch per private repository;
- add only the minimum temporary adapter needed to build frozen Ferris and
  invoke the unchanged owner and scenario runners on hosted Ubuntu;
- do not merge temporary hosted-validation branches; and
- remove temporary branches after evidence custody.

## Completion condition

- all five owner-integrity gates pass on both platforms;
- every existing scenario has a complete two-platform disposition;
- repeated plan, selection, and typed-result identities are stable within each
  platform;
- independent expected closures and dispositions match;
- no selected-pass/full-fail divergence occurs;
- all declared matched-failure controls remain matched failures;
- typed rejections run no owner command;
- detailed evidence remains private and public results remain aggregate;
- all temporary hosted-validation branches are removed; and
- all required role dispositions and documentation validation complete.

## Stop conditions

Stop rather than expand if execution requires:

- a Ferris product, schema, dependency, or command change;
- a corpus scenario, topology, owner command, expected result, or evidence
  schema change;
- weakening an owner oracle, identity comparison, or typed rejection;
- credentials in plans, logs, outputs, or committed evidence;
- a retry after a scenario or owner command starts;
- a sixth corpus, new scenario, or successor feature; or
- a production, support, savings, performance, or affected-only gating claim.
